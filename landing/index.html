Android package investigation

Local static

Package and split inventory, manifest permissions, exported components, resource configuration, byte references and endpoint strings.

  • APK, XAPK and APKS intake
  • Manifest and configuration findings
  • Artifact hashes and coverage records
Open APKTrust

Repository inspection

Local static

Immutable public GitHub snapshots or uploaded source archives. Inspect source with built-in rules, Python AST, JavaScript/TypeScript parsing, Semgrep and Bandit. Additional engines check credentials (Gitleaks), workflows (zizmor), package advisories (Trivy, OSV-Scanner and Grype), SBOM inventory (Syft), and bounded signatures (YARA-X).

  • Files, findings and source side by side
  • Decoded evidence and static relationships
  • Dependency inventory, advisory findings and explicit coverage
Open RepoSentinel

Optional external context

Android workspace

Configured VirusTotal and URLhaus reputation checks, hosted AI evidence synthesis, and Firebase Test Lab Robo execution.

  • Provider availability stays visible
  • Separate consent for APK cloud uploads
  • AI commentary stays separate from findings

Keys, access and provider limits apply. RepoSentinel can also use the same configured AI providers for optional findings commentary after explicit consent; repository source is not uploaded.

File and binary triage

Local static · partial coverage

Record file identity and hashes, then inspect bounded headers for common executable and container formats. Raw samples are removed after analysis; no target is executed, loaded, or installed.

  • SHA-256, SHA-1 and MD5 identity
  • Basic PE, ELF, Mach-O, ZIP and PDF metadata
  • Host isolation mode and unavailable engines shown in coverage

Deep disassembly, signatures, emulation and disposable-VM analysis are not integrated in this initial release. Metadata is not a safety verdict.

Save review decisions and export reports. JSON, HTML and SARIF keep evidence portable; repositories also export a CycloneDX inventory.

Clarity includes the limits.

AEGIS is an evidence workbench, not a safety certificate. Incomplete coverage, no detections or unavailable engines do not establish that a package or repository is safe.

Reports stay local. GitHub intake contacts GitHub. Android reputation, hosted AI and cloud execution involve external providers when selected. Repository reports remain PARTIAL; full Android decompilation and complete runtime coverage are not provided.

What does the introduction progress mean?

It is a short welcome animation that plays on each visit or reload of the AEGIS home page. The percentage describes the introduction sequence, not a security scan or analysis completion.
